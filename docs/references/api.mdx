# Platform API Reference

This page is the landing page for Charm platform API reference material. It separates public app-facing APIs from internal operational APIs.

## Planned Endpoint Groups

- Agent execution.
- Runs and threads.
- Billing and wallet.
- Store publishing.
- OAuth and integrations.
- Internal operations.

## API Categories

### Runner APIs

Runner APIs start and manage agent execution.

Examples:

- execute an agent,
- complete a run,
- read run status,
- read logs or traces.

### Store APIs

Store APIs support publishing, agent discovery, checkout, and user-facing app flows.

### Billing APIs

Billing APIs handle wallet state, checkout, Stripe webhooks, subscription state, revenue events, and creator payouts.

### Integration APIs

Integration APIs check OAuth connection state and help route users into provider authorization flows.

### Internal APIs

Internal APIs are for cron jobs, operational maintenance, migration support, and service-to-service callbacks. These endpoints should not be treated as public product APIs.

## Authentication

API routes may use different auth models:

- Supabase user bearer token for user-facing requests.
- Runner secret for internal callbacks.
- Cron secret for scheduled jobs.
- Provider-specific webhook secrets for external services such as Stripe.

Each endpoint group should document the required auth before this page is considered complete.
